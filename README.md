# 双语音声工作流 v2.2.7

[![GitHub](https://img.shields.io/badge/GitHub-weizhigao21%2FBilingual--Audio--Workflow-blue)](https://github.com/weizhigao21/Bilingual-Audio-Workflow)

基于 PyQt6 的三步式配音工作流工具：**字幕提取 → 语音合成 → 音频混音**，一键批量处理，输出双语配音视频/音频。

**v2.2.7（2026-10-16）**：修复任务状态更新。更换字幕或配音后正确重置下游结果；重跑混音会重新生成成品；取消批量执行后保留已完成结果，其余任务可重试；后台进度不会覆盖当前选中的任务；已有成品正确计入完成数。新增 20 项回归测试，全量 **270 passed / 24 subtests passed**。使用方式见 [任务状态与重跑](#任务状态与重跑)，完整记录见 [CHANGELOG](CHANGELOG.md)。已有 EXE 需重新运行 `打包.bat` 才能使用本次更新。

## 功能概览

| 步骤 | 功能 | 说明 |
|---|---|---|
| 步骤1 | 字幕提取 | 调用 faster-whisper（infer.exe）从视频/音频中提取 LRC 字幕 |
| 步骤2 | 语音生成 | 使用 Edge TTS / API 将字幕文本合成为配音片段；支持声笺链接读取音色并批量生成 |
| 步骤3 | 音频混音 | 将配音混入原始音频，支持声道定位、起拍对齐、内容对齐 |

## 界面

主窗口为**侧栏 + 中央**两区（声笺风格工作台，208px 侧栏）：

```
┌────────────────┬──────────────────────────────────────┐
│ 品牌 / 版本     │ 当前任务（紧凑标题行，悬停看全路径）    │
│ ＋ 添加素材     │ 工具栏（打开工作区 / 配置 / 批量执行） │
│ 任务队列        │ 步骤卡 1–3（状态药丸 · 进度 · 开始/停止 · 配置）│
│ （文件树）      │ 运行日志（吃掉剩余高度）               │
└────────────────┴──────────────────────────────────────┘
```

- **侧栏任务队列**：文件夹分组 → 子目录 → 音频任务的树形结构，用 `├ / └` 连接线表示从属关系（展开的父节点向下引一条连续竖线，子项用横线挂上去）；每行左侧状态点（等待 / 进行 / 完成 / 失败）、第二行状态词、右侧百分比。侧栏窄，第二行只放状态词，完整信息（三步标记、错误原因）在悬停提示里。
- **步骤卡**：字幕提取 / 语音生成 / 音频混音三张卡各自带状态药丸、「开始」「停止」与配置入口；**＋ 添加字幕** 在字幕提取卡内、**＋ 添加配音** 在语音生成卡内（用于跳过前置步骤）。卡片高度恒定（没有输出时显示"尚未生成"占位），切换任务不会跳动。
- **分区策略：白表面 + 边界线**。三种表面（卡片 / 工作区 / 侧栏）保持白或近白，功能区域靠**看得见的 1px 边界线**划分——侧栏右缘、页头分隔线、每张卡片的外框。边界线色 `#d4d4da` 与白底差 42 灰阶，1x 屏上清楚可见（旧 `#eeeeee` 只差 17，等于没有边界，正是"区域区分不明显"的根源）。步骤卡另有**左缘 3px 状态色条**（等待灰 / 进行中橙 / 完成绿 / 失败红），宽度钉死 3px，切状态不产生横向跳动。曾试过灰阶分层（灰底 + 白卡），反馈偏"脏"，已弃用。
- **主题**：全部样式集中在 `src/ui_theme.py`（objectName + 动态属性匹配，禁止内联 `setStyleSheet`），改配色 / 间距只动这一个文件。需要 QSS 背景或边框的 `QWidget` 子类要继承 `StyledWidget`。勾选图标是 `resources/ui/check.png`（打包时排除 Qt6Svg，只用 PNG）；它的路径由 `resource_url()` 解析，**打包后必须走 `sys._MEIPASS`**（onedir 的 datas 在 `_internal/`，不是 exe 同级目录），否则图标静默丢失、勾选框变成纯黑方块。
- **界面自查**：`python ui_preview.py` 离屏渲染各界面到 `_preview/*.png`（`window / idle / settings / panels / setup / metadata / deep / addmedia` 八个场景；需设 `QT_QPA_FONTDIR=C:/Windows/Fonts`，否则中文显示成方块）。配套的 `tests/test_ui_theme.py` 用像素断言守住这些视觉约定。

## 首次启动

1. 运行 `python main.py`
2. 在弹出的配置对话框中指定 **faster-whisper 项目路径**（`infer.exe` 所在目录）和 **工作区目录**
3. 点击 **保存并开始** 后进入主界面；暂未部署 faster-whisper 时，可点击下方 **跳过字幕提取，进入主界面**，下次启动不再重复弹出引导

跳过后字幕提取及完整自动流水线不可用。请自行准备字幕，通过「字幕提取」卡片里的 **＋ 添加字幕** 关联，或导入音频旁的同名字幕，再执行语音生成和混音。批量界面会明确提示缺少路径并禁用字幕提取步骤；已有字幕的任务仍可使用语音→混音流水线。稍后可通过工具栏的 **配置** 补充含 `infer.exe` 的目录，恢复自动字幕提取。

## 使用流程

### 单个任务

1. 拖拽视频/音频文件到任务列表，或点击侧栏的 **＋ 添加素材 → 视频 / 音频文件**
2. 程序自动识别同目录字幕文件并关联

### 文件夹分组导入

- 拖入**文件夹**（或点击 **＋ 添加素材 → 文件夹**）时，会创建一个"文件夹任务组"节点，展开显示文件夹内的**音频树**（每个音频文件一个子任务）
- 导入文件夹时不再弹出预览，程序直接匹配音频与同名字幕并创建任务；不需要的文件或子目录可在左侧文件树右键移除
- 疑似混音输出（`双语/`、`双语-*`、`_mixed` 文件）、自定义导出目录与工作区音频会自动排除；旧版 `.mix.json` 成品也仍可识别；已在任务队列的源文件不会重复导入
- 若多个音频将写到同一混音成品路径，后续冲突项会跳过并写入日志；混音输出与源文件同路径时也不会覆盖源文件
- 音频树保留导入目录的子文件夹层级；子目录节点显示完成数和进度，选中后可只执行该目录及其后代任务
- 右键子目录可一次移除其下全部任务，或重跑该目录内某一步；移除仅影响任务列表和恢复记录，不删除源音频与已生成文件
- 组节点实时显示整体进度与完成数（第二行为 `完成数/总数`，如 `1/2`，右列为百分比）
- 选中文件夹组后点步骤面板的“开始”：字幕提取按导入目录集中执行；语音生成和混音按任务执行
- 右键组节点可**移除整个文件夹组**或**重跑组内全部步骤**；拖入的单个文件为散任务，选中组时拖文件会加入该组

### 跳过步骤

- **＋ 添加字幕**（「字幕提取」步骤卡内）：直接指定字幕文件，跳过步骤1
- **＋ 添加配音**（「语音生成」步骤卡内）：直接指定配音目录（含 .wav 文件），跳过步骤2
- **自动检测**：添加任务时自动检测已存在的字幕、配音文件和双语输出，跳过对应完成步骤

### 任务状态与重跑

- **更换字幕或配音**：通过“＋ 添加字幕”或“＋ 添加配音”替换输入后，对应步骤及下游旧结果会重新判定。显式指定的配音目录仍可使用，匹配当前字幕和配置的配音缓存仍可复用；旧混音必须重新生成。重置只清除任务中的旧输出引用，不删除磁盘上的文件。
- **重跑**：任务、文件夹组或子目录的右键菜单可重跑指定步骤；后续步骤一起回到待处理。重跑混音会绕过“跳过已有文件”，更换字幕或重新配音后的下一次混音同样会重新生成。
- **取消与重试**：停止执行后，已成功生成的结果保留，取消的步骤回到待处理，可再次启动；其他未开始的任务保持原状。取消不会强制把进度推到 100%。
- **切换任务**：执行期间可以查看其他任务或目录，后台任务的进度与完成通知不会覆盖当前选择；切回正在执行的单任务时恢复其最新进度。
- **完成状态**：自动检测到的已有成品也计入完成数。文件夹步骤卡分别显示各步骤的完成比例，侧栏显示整组进度。
- **运行保护**：单步与批量执行期间禁止重复启动和重跑；正在使用的输入不能替换。需要更换输入时，先停止当前执行。

### 批量执行

- 三种模式：
  - **流水线**（默认）：字幕集中识别，**每份字幕就绪后立即更新任务状态并生成语音**，语音完成即混音；后续音频继续识别，无需等待整批字幕结束
  - **按任务**：每个任务依次执行全部步骤，再跑下一个任务
  - **按步骤**：所有任务先跑步骤1，再全部步骤2，再全部步骤3
- 步骤1 在默认流水线、按步骤及文件夹组模式下统一启动 infer.exe：完整导入目录直接递归识别；从文件树移除部分音频后，将剩余文件一次传入。同名音频位于不同子目录时字幕写回各自目录，不会相互覆盖。仅在 Windows 命令行过长时分批启动
- 步骤3 并行模式：多线程同时混音多个任务（可在混音配置中设置线程数）
- 任务和文件夹分组会写入工作区，重启后自动恢复；上次中断的步骤会回到待处理状态
- 批量/文件夹组执行时，三个步骤进度条按"任务间累计 + 任务内片段进度"平滑混合显示（语音的片段级进度实时可见，不再"长时间不动后猛跳"）

## 配置面板

### 字幕配置（步骤1，通过 **字幕配置...** 按钮打开）

| 参数 | 说明 |
|---|---|
| 推理设备 | auto / cpu / cuda |
| 计算精度 | float32 / float16 / int8 |
| 字幕格式 | lrc / srt / vtt |
| VAD 阈值 | 语音活动检测灵敏度 |
| 最小静音/语音时长 | 控制段落切分粒度 |
| 段落合并 | 合并短片段，设置最大间隔和时长 |

### TTS 配置（步骤2，通过 **TTS 配置...** 按钮打开）

| 参数 | 说明 |
|---|---|
| TTS 模式 | Edge TTS（免费在线）/ API 服务器（自定义服务器或声笺本机服务） |
| 声音 | Edge 模式提供 6 个普通话声音：晓晓、云希、晓艺、云健、云夏、云扬 |
| 声笺链接 | API 模式下粘贴声笺接入链接，点击“读取音色”添加或复用该服务入口，保留其他 API 配置 |
| 音色 / 刷新音色 | 选择声笺已保存的声音预设；新增或修改预设后点击“刷新音色”，不可用音色显示原因 |
| 语速 / 音量 | 百分比调节 |
| 线程池数量 | Edge 模式全局共享线程池的线程数（默认 5），所有音频共用同一个池、不随音频数叠加，控制同时可运行的任务数 |
| 全局并发上限 | Edge 模式真正放行的并发请求数上限（默认 8），池内多余任务排队，过高会触发微软服务限流 |
| 流水线语音并行 | 流水线模式下同时进行语音生成的音频数（默认 2，设 1=按音频逐个生成） |
| 批量 API | 单次请求发送多个文本，减少网络开销 |
| 缓存信息 | 显示当前缓存条数、总大小和累计复用次数；语速、音量、声音或 API 来源变化时重新生成对应配音 |
| 清除缓存 | 一键删除所有 TTS 音频缓存，释放磁盘空间 |

> Edge 合成端点说明：微软自 2026-10 起只接受 `api.msedgeservices.com` 上的合成请求，旧的 `speech.platform.bing.com` WSS 端点返回 403。程序在启动时自动切换到新端点（与网络、代理无关），无需任何设置；若 403 仍出现，请确认系统时钟准确并更新到最新版程序。

### 连接声笺并批量生成

需要 **声笺 v0.7.11 或更新版本**，以及包含本次联动功能的双语工作流源码。两个程序在同一台电脑运行，生成期间保持声笺本机服务开启。

1. 在声笺的**声音库**保存要使用的声音预设，包括所选模型、生成方式、内置音色或参考音频、声音描述及生成参数。列表读取的是已保存的预设；只有模型文件、尚未保存的临时配置不会出现在列表中。
2. 在声笺的**工作流联动**页面点击**复制接入链接**。默认链接为 `http://127.0.0.1:8765/workflow`，修改过服务端口时使用页面显示的实际链接。
3. 打开双语工作流的 **TTS 配置...**，TTS 模式选择 **API 服务器**。在 **声笺链接** 中粘贴链接，点击 **读取音色**；程序添加或复用 **声笺 · 本地音色** 服务入口并选中它。
4. 在 **音色** 下拉框选择需要的预设。列表显示音色名称与模式，悬停可查看模型、语言、内置音色及不可用原因；模型名称和版本标签自动保存，无需手动填写。若只使用这一音色配音，关闭 **多API轮询（失败自动切换下一个）**。
5. 按需勾选 **使用批量API（加速合成）** 并设置 **批量大小**，随后按原有方式导入视频/音频及字幕，执行语音生成或批量流水线。已有字幕可跳过字幕提取。

工作流将字幕片段提交给声笺，等待生成并下载 WAV，序号、时间戳和配音目录规则保持一致，完成后继续混音。使用声笺 v0.7.11+ 时只保留数据库生成记录，不创建声笺侧栏作品，不写入声笺永久音频缓存。新版适配器把音频保存到工作流输出目录并校验 WAV 后发送接收确认，声笺删除临时文件，保留模型、文本、声音预设、生成时间、时长和结果。工作流自己的音频文件与缓存保留，供后续混音使用。

同一运行的多个批次共享内部记录标识，每批只查询和下载自己的片段；部分失败仍保留成功输出。取消只停止并清理本批未接收的音频，其他批次不受影响。未接收音频在整批结束 1 小时后由声笺清理，重启继续执行。已有工作流记录不再出现在声笺侧栏，历史音频清理保留数据库元信息以及普通创作和参考声音使用的共享文件。旧工作流 EXE 连接新版声笺时，在完整下载后自动清理；新版接收确认需重新打包工作流或从源码启动。

批量大小控制一次提交的字幕数量；声笺 **设置 → 批量性能** 中的并发数控制同时生成多少条，支持 1–4 个独立统一引擎实例，并可设置每实例 CPU 线程。默认 1 个实例、CPU 线程自动分配；测试 2 个实例时，批量大小需至少为 2。并发会增加内存和显存，显存不足时声笺将当前任务降为单实例并重试一次；普通创作、Windows 系统声音和备用 Python 后端保持串行。

本机 RTX 2080 Ti 的 VoxCPM2 BF16 短文本实测中，相同 4 段、每实例 4 CPU 线程：单实例约 12 秒，双实例约 25 秒，双实例整卡显存约 10.1 GiB，因此该模型默认保持单实例。增加线程或提高资源占用不保证提速，其他模型应比较实际生成时间后调整。性能设置由声笺保存，不改变音色预设和原有音频缓存身份。

**音色更新与缓存**：新增预设后点击 **刷新音色**；重启工作流后打开已连接的 API 参数页会自动读取列表。每项语音任务开始前会再次读取所选音色的配置版本，同步保存版本信息，再计算输出目录和缓存标识；预设参数变化后，新生成不会复用旧版本的缓存。一次语音任务使用固定版本，生成途中预设变化会明确报错。要为已经完成的任务重新配音，在任务列表右键重跑语音生成，并重新混音。

| 现象 | 处理方式 |
|---|---|
| 找不到“声笺链接”或“音色” | 确认运行的是更新后的源码；旧版 EXE 需要重新打包 |
| 读取失败或连接被拒绝 | 确认声笺已启动本机服务，重新复制当前接入链接；目前支持 `127.0.0.1` / `localhost` 的本机链接。Edge 模式下不读取音色，也不会产生该错误 |
| Edge 模式下看不到“音色”下拉框 | 音色仅在 API 服务器模式下生效，切回 API 模式后自动读取 |
| 没有可用音色 | 先在声笺保存声音预设，再刷新列表 |
| 音色置灰、提示模型或参考音频缺失 | 根据提示在声笺修复模型路径或参考音频，再刷新；可用状态检查配置和文件，实际推理错误仍会在生成时显示 |
| 已选音色被删除 | 刷新并重新选择音色，程序不会自动换成另一个声音 |
| 每批字幕都创建一个声笺任务 | 更新并重启声笺至 v0.7.0+，同时更新本工作流适配器；旧 EXE 需重新打包 |
| 增加线程没有提速或显存不足 | 在声笺的「批量性能」降低并发；VoxCPM2 BF16 在本机双实例实测更慢，建议保持 1 |
| 生成途中提示预设版本变化 | 确认声笺配置后重新生成；已完成片段会保留 |

原有 Edge TTS 和手工配置的其他 API 仍可使用；音色自动发现仅用于通过声笺链接接入的服务。

### 混音配置（步骤3，通过 **混音配置...** 按钮打开）

| 参数 | 说明 |
|---|---|
| 导出格式 | MP4（复制源视频码流并替换音轨）/ MP3 / M4A（AAC）/ WAV（无损）/ AAC；视频也可导出纯音频 |
| 音频质量 | 档位预设：低（128k/44.1kHz）/ 标准（192k/44.1kHz）/ 高（256k/44.1kHz）/ 极致（320k/48kHz）/ 自定义 |
| 比特率 | 128k / 192k / 256k / 320k（自定义档位时可选） |
| 采样率 | 44100 Hz / 48000 Hz（自定义档位时可选） |
| 声道 | 立体声 / 单声道（自定义档位时可选） |
| WAV 位深 | 16 / 24 / 32 bit（仅 WAV 导出生效） |
| 音量 | 配音相对原音频的音量偏移（dB） |
| 自动音量 | fixed（匹配原音频 RMS 响度）/ auto（逐帧动态匹配）/ off（纯固定增益） |
| 声道检测 | 自动检测**原音频人声**的方位（左/中/右），据此把配音放到对侧；判不出侧向信息时按「原音居中时」处理 |
| 配音分离度 | 0–90°：原音人声判在左/右时，配音放到**对侧**的偏转幅度（0° 始终居中，90° 完全放到对侧）。右侧实时显示换算后的左右角度（如 `偏转 45° → 135° / 45°`） |
| 原音居中时 | 原音人声在中间、或检测不出声道时的配音落点：偏左 / 正中 / 偏右 |
| 起始对齐 | 跳过配音片段的静音起始部分，对齐到原音频起拍点 |
| 内容对齐 | 用原音频人声起始点纠正字幕时间戳误差 |
| 峰值保护 | 默认保真模式：超出 -1 dBFS 时整段统一衰减，保留动态和声像；可选旧版软限幅 |
| 高质量重采样 | 默认开启，采样率不同时使用 FFmpeg 64 点滤波；片段很多时可关闭以加快处理 |
| 导出目录 | 自定义输出路径（默认输出到源文件目录下的 `双语/` 文件夹） |
| 输出目录前缀 | 文件夹导入时输出目录带源文件夹名（`双语/` → `双语-yuyu/`，输出直接在该目录根，不嵌套子目录；勾选后源文件夹不再被重命名） |
| 线程数 | 批量混音时的并行任务数（流水线模式的混音并行度同样受此控制；注意并行混音内存叠加） |
| 长音频磁盘缓冲 | 默认 20 分钟起使用磁盘映射混音以降低内存占用；设为 0 表示始终使用。处理期间需要临时磁盘空间，任务结束或取消时会清理 |
| 作品信息 | 勾选“导出时写入作品信息”，点击旁边“编辑信息...”选择标题、艺术家、专辑、备注和程序版本；可用 `{文件名}` 填入每个任务的音频文件名 |

混音导出不再在成品旁生成 `.mix.json`。程序版本和不可嵌入的作品信息保存在工作区已有的 `task.json`；默认开启作品信息写入，MP3、M4A、MP4 和 OGG 的所选标签会写入成品。关闭开关时不写入程序提供的标签。混音完成后仍可从任务列表右键选择**编辑混音成品信息…**，单独修改某个成品的标题、艺术家、专辑和备注，保存时不会重新编码音频。WAV 和原始 AAC 的通用标签兼容性有限，其编辑信息只随工作区任务记录保存；单独移动成品文件不会带走这些字段。旧版 `.mix.json` 可继续读取，程序不会自动删除。修改混音导出设置后若要更新已有成品，可在任务或目录右键菜单重跑步骤3，无需手动关闭“跳过已存在的输出文件”。

混音优化与测试结果见 [混音优化说明](混音优化说明.md)。音频使用 CPU 编码，视频画面直接复制，因此不再提供无实际作用的 NVENC 音频开关。旧配置里的 `use_gpu`、`pipeline_mix_workers` 等废弃键会在启动加载配置时自动剔除并回写，无需手工清理。旧版的三个声道角度（`channel_map`）会在下次打开混音配置时自动折算成「配音分离度 + 原音居中时」（精确无损，出厂默认值可原样迁回），无需手工换算。

质量优先可保持“高质量重采样 + 保真峰值保护”，保存母版时选 WAV 24bit。峰值保护可能降低整段音量，且不等于过采样真峰值限幅；有损编码后仍可能出现峰值变化。对比新旧输出前，应取消“跳过已存在的输出文件”或选择新的导出目录。

本轮项目检查与已修复问题见 [项目优化检查](项目优化检查-2026-09-26.md)。TTS 输出目录记录生成配置，设置变化后原任务的配音和混音状态会重置；若先前已有成品，新混音会覆盖该任务对应的旧成品。批量流水线只执行勾选的步骤，单个配音片段失败时整项语音任务会报失败。

后续复检与修复见 [项目复检报告](项目复检报告-2026-10-10.md)：长音频混音遇到损坏/为空的配音片段时只跳过该片段而不再整段失败；配音片段列表会过滤 0 字节文件；批量执行结束时统一清理片段列表缓存；`resources/logs` 下超过保留期（30 天）的历史日志会在启动时自动清理。

## 配音文件命名与缓存规则

配音产物的名字由 **字幕内容** 和 **配音配置签名** 两样东西算出来。片段文件名只描述"这句话在字幕里的位置"（序号 + 时间轴），模型/声音身份全部落在上一层的**目录名**里——这样切换模型时混音器的时间轴编号不会错乱，两个模型的片段也不会再写进同一个目录。

计算过程集中在 `src/steps/tts_profile.py`（`profile_key` / `dir_name` / `legacy_dir_name` / `api_cache_model`）。

### 1. 输出目录：`workspace/<目录名>/`

```
目录名 = md5( 字幕文件字节内容 + "|" + profile_key(配音配置) )[:8]
```

`profile_key` 把配音配置归一化成一段 JSON 后取 sha256：

| 模式 | 参与计算的配置 | 归一化后的 JSON |
|---|---|---|
| Edge | 声音、语速、音量 | `{"mode": "edge", "rate": "+0%", "voice": "zh-CN-XiaoxiaoNeural", "volume": "+0%"}` |
| API | 生效的 API 列表（`url` + `model` + 可选「模型标签」）、是否启用批量请求 | `{"apis": [["http://127.0.0.1:8000", "八重神子_ZH"]], "bulk": true, "mode": "api"}` |

- 多 API 模式下取所有"状态为可用"的 API，单 API 模式取当前选中的那一条。
- **只有填了「模型标签」才会把它算进 JSON**（变成 `["url", "model", "标签"]`）；留空时 JSON 与旧版本逐位一致，既有目录与缓存不会整体失效。
- 声笺链接接入的音色会自动填写带版本的模型标识和模型标签，并在语音生成开始前同步预设版本；切换音色或修改预设配置时，新生成使用相应的输出目录与缓存身份，无需手工编辑标签。

计算示例（字幕内容 `[00:00.00]学长好厉害`）：

```
字幕文件字节  b'[00:00.00]\xe5\xad\xa6\xe9\x95\xbf\xe5\xa5\xbd\xe5\x8e\x89\xe5\xae\xb3\n'
profile_key  b2bb6660ad831930b2a2d2d6bcf7201a28740b43d442346373ed7e7f025cafa8
拼接后取 md5 再截前 8 位  →  5d5164c9
最终路径  workspace/5d5164c9/
```

同一份字幕、不同配置 → 不同目录，两套配音可以并存、互不覆盖：

| 配音配置 | 目录名 |
|---|---|
| Edge · 晓晓 · 语速 +0% | `5d5164c9` |
| Edge · 云希 · 语速 +0% | `508c16ce` |
| Edge · 晓晓 · 语速 +10% | `d56e2b84` |
| API · `127.0.0.1:8000` · `八重神子_ZH` · 无标签 | `a4044771` |
| API · 同一 URL 同模型 · 标签 `GPT-SoVITS-女声A` | `423c3b0f` |

### 2. 片段文件名：`{序号}_{时间戳}_{文本前2字}.wav`

```
safe_text = re.sub(r"[^\u4e00-\u9fa5a-zA-Z0-9]", "", 字幕文本)   # 去掉标点、空白、符号
文件名     = f"{序号:04d}_{时间戳（':' 换成 '-'）}_{safe_text[:2] or '无'}.wav"
```

- **序号**：该字幕文件内的第几条（从 `0001` 起），混音器按它排序还原时间轴；**时间戳**：字幕时间轴，LRC 的 `[mm:ss.xx]` 归一成 `HH-MM-SS.CC`。
- 文件名里**没有**模型、声音、API 信息；取不到可用字符时文本段固定为 `无`。

| 字幕文本 | 时间戳 | 文件名 |
|---|---|---|
| `学长…好厉害♪？` | `00:00:00.00` | `0001_00-00-00.00_学长.wav` |
| `…`（无可用字符） | `00:01:02.30` | `0007_00-01-02.30_无.wav` |

混音器按 `^(\d{4})_(\d{2})-(\d{2})-(\d{2})\.(\d{2})_(.+)\.wav$` 解析（`src/steps/audio_utils/mix_files.py`）：序号定顺序、时间戳定位置。

### 3. 音频缓存：`resources/tts_audio_cache/<键>.wav|.mp3`

```
Edge: md5( f"{文本}|{声音}|{语速}|{音量}|edge_tts|{字幕mtime秒}" )   → .mp3
API : md5( f"{文本}|{model}|{url}[|{模型标签}]|{字幕mtime秒}" )       → .wav
```

- SQLite（`resources/configs/tts_audio_cache.db`）记录文本内容、来源、文件大小与复用次数；命中缓存时直接复制到目标片段文件名，不再请求模型。
- **字幕版本**取字幕文件的修改时间（整数秒）：字幕重新导出后旧缓存自然失效、重新合成。
- 手工配置的 API 在同一个 URL 上换了模型时，把「模型标签」填成不同值即可分开缓存；不填标签则与旧版本键一致。通过声笺链接接入时由程序自动管理版本标签。

### 4. 历史目录的兼容与迁移

v2.1.19 及更早版本的目录名只哈希字幕内容（例如 `ff5a8887`）。程序在**导入任务**和**启动恢复任务**时会检查这类旧命名目录：

- 目录名恰好等于"当前字幕内容的旧命名" **且** `.tts_profile.json` 里的签名与当前配置一致 → 原地 rename 成新命名并复用，**不重新生成语音**；
- 签名不一致（换过模型/声音）或改名失败（目标已存在、目录被占用）→ 视为"没有可用配音"，重新生成到新命名目录，避免"检测到的目录"与"实际生成目录"分叉；
- 手工改过名的目录、自定义配音目录（不在 `workspace/` 下）不参与迁移。

换模型会产生新目录，旧模型那套配音目录会保留（这是"换模型 = 换目录"的代价）；确认不再需要时，可手动删除 `workspace/` 下多余的目录。

注意：从任务列表移除任务、或用「全部清空」删除任务目录，都**不会**删除配音目录 `workspace/<目录名>/`（它是按内容寻址、可被其他任务复用的）。长期使用后 `workspace/` 会累积这类目录，目前需要手动清理；相关回收入口见 [项目复检报告](项目复检报告-2026-10-10.md)。

## 音频缓存

TTS 合成结果按 **文本、声音/模型、生成设置及 API 来源** 区分缓存（SQLite + 本地音频文件），缓存位于 `resources/tts_audio_cache/`；键的完整算法见上一节 [配音文件命名与缓存规则](#配音文件命名与缓存规则)。

可通过 **TTS 配置 → 清除缓存** 按钮一键清理，或手动删除 `resources/tts_audio_cache/` 目录和 `resources/configs/tts_audio_cache.db`。运行日志位于 `resources/logs/`，按天命名，超过 30 天的历史日志会在启动时自动清理。

**v2.2.6（2026-10-13）**：重做界面分区方式。截图反馈"区域区分不明显、太亮、不知道看哪里"——像素扫描确认三种表面全是白（卡片 / 工作区 `#ffffff`、侧栏 `#fafafa`，亮度差 0 和 5），唯一边界是 1px `#eeeeee`（与白底只差 17 灰阶，等于没有边界）。先试"灰阶分层"（灰底 + 白卡）被判偏脏，定稿为**白表面 + 边界线**：表面全部回白，分区改由看得见的边界线承担（侧栏右缘 / 页头分隔线 / 卡片外框），边界线加深到 `#d4d4da`（与白底差 42）。同时切开 `border`（区域边界）与 `separator`（卡内二级分隔）的职责、拆分被复用的语义色、步骤卡加左缘 3px 状态色条。守卫测试 63 → 67 项，全量 217 passed。同一版本还修掉一个**打包专属缺陷**：`_resource_dir()` 在 frozen 下用 exe 同级目录找资源，而 PyInstaller 6 的 onedir 把 datas 放在 `_internal/`（= `sys._MEIPASS`），导致 `check.png` 解析为空、**打包版所有勾选框都退化成纯黑方块**（源码运行看不出来）；现改为优先 `sys._MEIPASS`，并补 `BundledResourcePathTests` 两条守卫，全量 219 passed。**注意：此修复须重新执行 `打包.bat` 后打包版才生效。**

同版本还重做了**声道角度**：把旧版三个各自独立的 0–180° 数字框收敛成两个参数——**配音分离度**（0–90° 滑块，原音人声判在左/右时配音放到对侧的幅度）与**原音居中时**（偏左/正中/偏右）。原来的 0°/180° 是单侧增益为 0（对侧完全听不到），检测器一判错人声就整段消失在一边，本不该给人手填；而用户实际总是把三个框调成 45–135° 的软声像，等于手动收敛成了一个。旧配置按 `(|left−90|+…)/2` 精确迁回（用度数存而非百分比），面板与混音共用同一个换算函数。顺带修掉旧检测器三处缺陷：判据改为归一化不平衡度 `|L−R|/(L+R)`（阈值 0.30，旧判据只相当于 0.091）、帧长按采样率换算到 ≈23 ms（旧版降采样后 ≈93 ms）、按 85–3000 Hz 人声带判定（旧版抽点降采样会让 21 kHz 别名进来）；检测结果附置信度并写日志。原计划的 VAD 语音门控经 300 例随机对照证明对判定 0 影响，已移除；设置面板的读数一度被滑块挤成 1px 竖线，已按最宽文案钉住最小宽度。新增 `tests/test_panning.py` 31 项守卫，全量 **250 passed / 21 subtests passed**。

**v2.2.5（2026-10-13）**：修复任务树展开箭头右侧多余的线头——横向肘线原本一律画到内容起点，比箭头右缘还远约 5px，末端就从箭头右侧露出来；现在有展开箭头时止于箭头左缘，既不留缝也不露头，无箭头的行仍接到内容起点。守卫测试 62 → 63 项。

**v2.2.0 – v2.2.4（2026-10-13）**：界面重构，依据五轮截图反馈迭代。以《声笺 UI 风格规范》为尺子做针对性体检（不照搬上游做法），完成四件事：

1. **主题集中化** —— 新增 `src/ui_theme.py`，色板 / 字号 / 尺寸 / QSS 全部集中一处，组件只用 objectName + 动态属性匹配样式，内联 `setStyleSheet` 清零。过程中修掉三个系统性缺陷：`QWidget` 的 Python 子类不会绘制 QSS 背景与边框（新增 `StyledWidget` 基类）、`windowOpacity` 对子控件无效（浮层改用 `QGraphicsOpacityEffect`）、勾选图标因 QSS 资源路径带 `file:///` 前缀而静默加载失败（改回纯路径）。
2. **结构精简** —— 主窗口由四区逐步收成「侧栏 + 中央」两区：移除右侧检查器与底部操作栏；「添加文件夹」与「添加视频/音频」合并为侧栏程序名下方的 **＋ 添加素材**（点开为统一选择窗）；「添加字幕」「添加配音」下沉到字幕提取 / 语音生成步骤卡内；日志卡吃掉中央区剩余高度。
3. **任务树重做** —— 修正委托双重缩进（`option.rect.left()` 已含层级缩进），改为标准 `├ / └` 连接线：展开的父节点向下引一条连续竖线，子项用横线挂上去；第二行文案按 208px 栏宽实测重新设计（状态词、`完成数/总数`），完整信息进悬停提示；长路径一律按像素省略。
4. **可视修正** —— 「已完成」改为明确绿色并统一状态点/日志配色；勾选框恢复正常打勾；步骤卡高度恒定（输出行改为占位而非显隐），消除切换任务时的界面跳动；步骤卡输出路径按宽度自适应省略，可点击链接保留。

守卫测试从 16 项扩到 63 项（主题常量、骨架、工具栏、任务树结构、勾选图标像素、日志配色、状态绿、卡片高度稳定性等），每轮修复均经破坏验证（改坏即失败、恢复即通过）。
